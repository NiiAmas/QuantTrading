1. Role Overview & Responsibilities

As the Lead Frontend Developer for the QuantTrading platform, my mandate was to design, engineer, and optimize the client-facing application. Financial trading platforms require immense data density, real-time updates, and flawless UX (User Experience). A single bug in the frontend could lead a user to misinterpret their portfolio value.

My core responsibilities included:

  • Architecting the Single Page Application (SPA) using React.
  • Designing a premium, "Molten Gold" dark-mode aesthetic that rivals professional tools like Bloomberg Terminal or Binance.
  • Consuming complex REST APIs built by the Backend Engineer and handling asynchronous data fetching.
  • Implementing a robust global state management system so the UI instantly reacts to backend database changes without requiring manual page reloads.
  • Integrating heavy third-party visualization libraries, including a 3D WebGL Globe and TradingView candlestick charts.

Deep Dive: The Dashboard Layout Logic

One of the most complex UI elements was the KPI metric boxes on the Dashboard. I had to ensure that the "Realized" and "Unrealized" balances did not overflow their containers on smaller screens.

// Inside Dashboard.jsx
<div className="flex flex-col gap-1 mt-2">
  <div className="flex items-center justify-between gap-2">
    <span className="text-[9px] text-gray-500 font-bold uppercase whitespace-nowrap">
      Realized
    </span>
    <span className="text-xs font-bold text-white whitespace-nowrap">
      ${stats?.realizedBalance}
    </span>
  </div>
</div>

Code Defense: The use of flex-col allowed me to stack the metrics vertically. The critical Tailwind classes here are justify-between (which pushes the label to the far left and the number to the far right) and whitespace-nowrap (which explicitly forbids the browser from breaking the text onto a second line, preventing the box from warping).

4. State Management (Zustand)

In a React application, "State" is the data currently loaded in memory. Without global state management, I would suffer from "Prop Drilling"—passing the user's account balance down through 5 layers of components.

I engineered useStore.js to act as the single source of truth for the frontend. When the backend database updates, this store fetches the new data, and React instantly updates every component on the screen.
// src/store/useStore.js
import { create } from 'zustand';

const useStore = create((set, get) => ({
  accounts: [],
  activeAccount: null,
  stats: null,
  
  setActiveAccount: (account) => {
    set({ activeAccount: account });
    // Automatically trigger a fetch for the new account's specific data
    get().fetchAccountData();
  },
  
  fetchAccountData: async () => {
    const { activeAccount } = get();
    if (!activeAccount) return;
    
    try {
      const response = await api.get(`/accounts/${activeAccount.id}/data`);
      set({ stats: response.data.stats });
    } catch (error) {
      console.error("Failed to fetch data", error);
    }
  }
}));

Code Defense: This code creates an immutable state tree. By defining setActiveAccount inside the store, the Sidebar component can call it when a user clicks a dropdown. The store then automatically makes an asynchronous Axios call to the backend API to fetch the new account's ledger, updating the Dashboard seamlessly.

5. Cross-Role Collaboration

🤝 Correlating with the Backend Engineer

The frontend is useless without data. I had to work intimately with the Backend Engineer to define the API contracts.

  • CORS Policy: Initially, my Axios requests were blocked by the browser. I diagnosed this as a Cross-Origin Resource Sharing issue. I instructed the Backend Engineer to update their FastAPI CORSMiddleware to explicitly allow requests originating from my frontend's IP address.
  • API Configuration: I created src/config/api.js to centralize the connection to the backend. We agreed that the backend would run on Port 8000. 
    import axios from 'axios';
const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://localhost:8000/api',
});
// Attach JWT Token to every request
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

🤝 Correlating with the Database Architect

While I didn't write SQL queries, the UI's design was heavily dependent on the Database Architect's schema design.

  • Data Separation: I requested that the DB Architect create a clear separation between "Available Cash" (the balance column in the Accounts table) and "Floating P&L" (the pnl_dollars column in the Trades table). Because they structured the database correctly, I was able to build a UI that accurately separates Realized vs Unrealized profits.
  • Spot Holdings vs Shorts: We collaborated on the logic for the Trading Hub. I needed the DB to only return physical PortfolioAsset rows for Long Crypto/Stocks, while hiding Shorts (since you don't "hold" a short). The DB Architect implemented this filtering before sending the JSON to my frontend.

6. Deployment & Build Workflow

When the code was ready for production, I couldn't just copy the raw React files to the server. Browsers do not understand JSX.

Step 1: The Build Process

I utilized Vite's highly optimized Rollup bundler to compile the application.

npm run build

This command transpiles all React JSX into plain, minified JavaScript, compiles the Tailwind classes into a tiny CSS file, and outputs everything into a dist/ folder. This reduces the application size by over 90%.

Step 2: Server Push (Rsync)

I correlated with the Systems Engineer to push my compiled code to the live DigitalOcean droplet using SSH.

rsync -avz --exclude 'node_modules' ~/QuantTrading/ root@188.166.155.154:/root/QuantTrading/

Command Defense: rsync is a delta-transfer algorithm. It compares my laptop to the server and ONLY uploads the files that changed, making deployments take 2 seconds instead of 10 minutes. The --exclude 'node_modules' flag is absolutely critical, as uploading gigabytes of development dependencies would crash the server.

7. Critical Challenges & Solutions

The ChallengeThe Engineering Solution
The "White Screen of Death" on Charts
The third-party react-ts-tradingview-widgets package was crashing React 18 silently due to Strict Mode double-mounting issues, leaving a massive white box on the screen.		 Resolved
I completely ripped out the buggy third-party npm package. I replaced it with an indestructible, native HTML <iframe> that connects directly to TradingView's widget embed URL. This bypassed React's lifecycle entirely, ensuring 100% uptime for the charts.
Z-Index Wars on the Dashboard
The 3D WebGL Globe was rendering "on top" of the custom dropdown menus and tooltips, making them unclickable.		 Resolved
WebGL contexts naturally fight the DOM for rendering priority. I applied strict z-index: 10 to the globe container and z-index: 50 to the floating React components in Tailwind to force the browser compositing engine to respect the stacking order.
