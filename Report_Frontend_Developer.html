01

Project Overview & Your Role as Frontend Developer

What Is QuantTrading?

QuantTrading is an AI-powered quantitative trading platform that automatically trades stocks, crypto, forex, and commodities using a 3-Layer Verification System: Technical Analysis + FinBERT Sentiment Analysis + Quantitative Analysis. The platform runs a continuous bot engine in the background, while users interact with a sleek React-based dashboard to monitor their portfolios, view AI trade decisions, read global news, and configure risk settings.

Your Role: Frontend Developer

As the Frontend Developer, you were responsible for:

  • Building the entire user interface — all 8 pages the user sees and interacts with
  • React component architecture — designing reusable, modular components
  • State management with Zustand — managing authentication tokens, account data, and settings
  • API integration — connecting every page to the backend's FastAPI endpoints using Axios
  • Real-time data polling — setting up intervals to refresh live portfolio data every 5 seconds
  • Authentication flow — login, register, Google OAuth, JWT token management
  • Styling with TailwindCSS v4 — a custom design system with a "Molten Gold" theme
  • 3D Globe visualization — integrating react-globe.gl for the geopolitical news map
  • TradingView charts — embedding professional-grade financial charts
  • Responsive design — dark/light theme toggle, custom scrollbars, animations

How Your Work Connects to the Other Two Roles

With the Backend Person: Every API call (axios.get, axios.post) in the frontend hits a FastAPI endpoint the backend person created. Your config/api.js file points to their server. You consume JSON responses they format. When the backend person adds a new endpoint, you build the UI that calls it.

With the Database Person: You never talk to the database directly. Instead, every piece of data you show on screen (account balances, trade ledger, news articles, portfolio positions) is data that was structured by the Database person's table schemas, stored by the Backend person's logic, and served to you through API endpoints. The column names in the database (like pnl_dollars, entry_price, trade_type) map directly to the JSON fields you destructure in your React components.

frontend/package.json — dependencies

Why: React is the core UI library. We use React 19 (the latest) which includes improvements like automatic batching, concurrent features, and better performance. react-dom is required to render React components into the actual browser DOM. Every single .jsx file in our project uses React.

Why: Enables client-side routing — navigating between pages (Dashboard, Trading Hub, Charts, etc.) without reloading the browser. We use BrowserRouter, Routes, Route, NavLink, Navigate, useNavigate, and Outlet.

3. Axios HTTP CLIENT

"axios": "^1.13.2"

Why: HTTP client for making API requests to our FastAPI backend. We chose Axios over the native fetch() API because Axios automatically parses JSON, handles errors better (throws on 4xx/5xx status codes), and supports request/response interceptors. Every page that shows live data uses Axios.

Key line in code: const res = await axios.get(`${API_URL}/accounts`, { headers: { Authorization: `Bearer ${token}` } });

Coordination with Backend: Every axios.get() or axios.post() in our frontend directly maps to a @app.get() or @app.post() decorator in the Backend person's main.py file.

"zustand": "^5.0.13"

Why: Zustand is a lightweight state management library (alternative to Redux). We chose it because: (a) it has zero boilerplate — no providers, reducers, or action types, (b) it's only ~1KB, (c) it works with React hooks naturally. We have two stores: useAuthStore (authentication state) and useStore (account/settings state).

Key line in code: const useAuthStore = create((set) => ({ token: null, isAuthenticated: false, login: async () => { ... } }))

"lucide-react": "^0.562.0"

Why: A modern icon library with 1000+ clean, consistent SVG icons. We use icons like Activity, LayoutDashboard, Wallet, TrendingUp, TrendingDown, Globe, Settings, LogOut, etc. throughout the entire UI. Foundation Files — index.html, main.jsx, index.css

frontend/index.html

The single HTML file that hosts our entire React app. This is a Single Page Application (SPA) — the browser loads this one HTML file, and React dynamically renders all pages inside the <div id="root"> element.

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>QuantTrading</title>
  </head>
  <body>
    <div id="root"></div>        ← React mounts the ENTIRE app here
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

Why type="module": Tells the browser to load the script as an ES Module, which supports import/export syntax natively. Vite requires this for its development server to work.

frontend/src/main.jsx — The Application Entry Point

This is the very first JavaScript file that runs. It bootstraps the React app:

import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { GoogleOAuthProvider } from '@react-oauth/google'
import './index.css'
import App from './App.jsx'

const GOOGLE_CLIENT_ID = "16736128830-60gc...apps.googleusercontent.com";

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <GoogleOAuthProvider clientId={GOOGLE_CLIENT_ID}>
      <App />
    </GoogleOAuthProvider>
  </StrictMode>,
)

Line-by-line breakdown:

  • StrictMode — Development helper that highlights potential bugs (double-renders in dev mode to catch side effects).
  • createRoot — React 19's new rendering API (replaces ReactDOM.render). Creates a root render container attached to the DOM element with id "root".
  • GoogleOAuthProvider — Wraps the entire app so Google Sign-In works on any page. The clientId is our Google Cloud Console OAuth 2.0 Client ID.
  • import './index.css' — Loads our global styles and Tailwind theme BEFORE any component renders.
  • <App /> — Our root React component that handles routing and layout.

🤝 Coordination — Google Client ID

The Google Client ID was set up on Google Cloud Console. The Backend person needed to know about this because their /auth/google endpoint receives the decoded email. Both Frontend and Backend had to agree: "Frontend decodes the Google JWT to extract the email, then sends just the email to the backend."

frontend/src/App.jsx — The Root Component & Router

This is the brain of the frontend. It:

  1. Checks if the user is authenticated (via Zustand store)
  2. If NOT authenticated → show <AuthPage /> (login/register screen)
  3. If authenticated → show the full app with sidebar, header, and page routing
  4. Manages the dark/light theme toggle
  5. Fetches the user's accounts on first load
import React, { useState, useEffect } from 'react';
import { BrowserRouter, Routes, Route, Navigate } from 'react-router-dom';
// ... all page imports ...
import useAccountStore from './store/useStore';
import useAuthStore from './store/useAuthStore';

export default function App() {
  const { fetchAccounts } = useAccountStore();
  const { isAuthenticated } = useAuthStore();
  const [theme, setTheme] = useState(() => localStorage.getItem('theme') || 'dark');

  // When user logs in, fetch their accounts from the backend
  useEffect(() => {
    if (isAuthenticated) {
      fetchAccounts();   // ← This calls GET /accounts with the JWT token
    }
  }, [fetchAccounts, isAuthenticated]);

  // If not logged in, show the auth page (no routing needed)
  if (!isAuthenticated) {
    return <AuthPage />;
  }

  // Authenticated: show the full app with all routes
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout theme={theme} toggleTheme={toggleTheme} />}>
          <Route index element={<Dashboard />} />
          <Route path="trading-hub" element={<TradingHub />} />
          <Route path="news" element={<NewsPage />} />
          <Route path="news/:id" element={<NewsDetail />} />
          <Route path="analysis" element={<TradeAnalysis />} />
          <Route path="charts" element={<Charts />} />
          <Route path="markets" element={<MarketsExplorer />} />
          <Route path="settings" element={<Preferences />} />
          <Route path="*" element={<Navigate to="/" />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}

Important concepts:

  • Nested Routes: All pages are nested under <Layout>, which provides the sidebar and header. The <Outlet /> inside Layout renders whichever child route matches.
  • Catch-all Route: path="*" redirects any unknown URL to the dashboard.
  • Theme Persistence: Theme preference is saved to localStorage so it survives page refreshes.

State Management — Zustand Stores

frontend/src/store/useAuthStore.js — Authentication State

What This Store Manages:

  • token — The JWT access token from the backend (string or null)
  • isAuthenticated — Boolean flag derived from token validity
  • loading — Loading state during login/register API calls
  • error — Error message from failed auth attempts

Key Function: login(email, password)

login: async (email, password) => {
  set({ loading: true, error: null });
  try {
    const formData = new URLSearchParams();
    formData.append('username', email);   // OAuth2 spec uses 'username'
    formData.append('password', password);

    const res = await axios.post(`${API_URL}/auth/login`, formData, {
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' }
    });

    const token = res.data.access_token;
    localStorage.setItem('token', token);   // Persist for 30-day sessions

    set({ token, isAuthenticated: true, loading: false });
    return true;
  } catch (err) {
    set({ error: err.response?.data?.detail || 'Login failed', loading: false });
    return false;
  }
}

Why URLSearchParams instead of JSON? The Backend person's /auth/login endpoint uses FastAPI's OAuth2PasswordRequestForm, which expects form-encoded data (application/x-www-form-urlencoded), not JSON. This is the OAuth2 spec standard.

Token persistence: We save the JWT to localStorage so the user stays logged in even after closing the browser. On app load, we check if the stored token is still valid by decoding its exp (expiration) claim.

Key Function: isTokenValid(token)

function isTokenValid(token) {
  if (!token) return false;
  try {
    const payload = JSON.parse(atob(token.split('.')[1]));
    return payload.exp * 1000 > Date.now();
  } catch { return false; }
}

How JWT decoding works: A JWT has 3 parts separated by dots: header.payload.signature. We split on '.', take the middle part (payload), base64-decode it with atob(), and parse the JSON. The exp field is the expiration timestamp in seconds — we multiply by 1000 to compare with JavaScript's millisecond-based Date.now().

🤝 Coordination — JWT Token Contract

The Backend person creates the JWT with python-jose library, encoding the user's email as "sub" (subject) and setting "exp" to 30 days. The Frontend trusts this token and sends it as Authorization: Bearer {token} in every subsequent API request. If the token expires, any API call returns 401, and the frontend auto-logs out.

frontend/src/store/useStore.js — Account & Settings State

What This Store Manages:

  • accounts — Array of all user's trading accounts
  • activeAccount — ID of the currently selected account
  • globalBalance — Sum of all account balances
  • settings — Platform settings (persisted to localStorage)
  • isWizardOpen — Whether the "Create Account" wizard is open

Key Function: fetchAccounts()

fetchAccounts: async () => {
  try {
    const token = useAuthStore.getState().token;
    const res = await axios.get(`${API_URL}/accounts`, {
      headers: { Authorization: `Bearer ${token}` }
    });
    const accounts = res.data;
    const globalBalance = accounts.reduce((acc, curr) => acc + curr.balance, 0);
    set({
      accounts,
      globalBalance,
      activeAccount: get().activeAccount || (accounts.length > 0 ? accounts[0].id : null)
    });
  } catch (err) {
    if (err.response?.status === 401) {
      useAuthStore.getState().logout();  // Token expired — force logout
    }
  }
}

Cross-store communication: Notice how useStore reads the token from useAuthStore using useAuthStore.getState().token. This is Zustand's way of accessing another store's state without React hooks (since we're inside an async function, not a component).

🤝 Coordination — Account Data Shape

The Backend person's GET /accounts endpoint returns an array like: [{ id: "1", name: "High Risk Fund", balance: 10000, type: "Aggressive", holdings: ["BTC-USD", "AAPL"], assetTypes: ["Crypto", "Stocks"], sectors: [...] }]. The Frontend relies on these exact field names. If the Backend person changes type to strategy, the Frontend breaks. This is the API contract.

Page-by-Page Breakdown — Every Page File Explained

pages/AuthPage.jsx — Login & Registration

What it does: Shows when the user is NOT authenticated. Contains a form with Email + Password fields, a toggle between "Sign In" and "Create ID" modes, and a "Sign in with Google" button.

Backend endpoints used:

  • POST /auth/login — sends form-encoded username + password
  • POST /auth/register — sends JSON with email, password, optional PIN
  • POST /auth/google — sends JSON with just the email (decoded from Google JWT)

Special feature — Password visibility toggle: Uses showPassword state with <Eye /> / <EyeOff /> icons to let users see what they're typing.

Google OAuth flow:

const handleGoogleSuccess = async (credentialResponse) => {
  const decoded = jwtDecode(credentialResponse.credential);
  const email = decoded.email;
  await useAuthStore.getState().googleLogin(email);
};

Google returns a JWT credential → we decode it to get the email → we send the email to our backend → backend creates/finds the user → returns our own JWT → frontend stores it.

pages/Dashboard.jsx — Main Dashboard with Globe

What it does: The main landing page after login. Shows 3 KPI cards (Account Equity, Active Investments, Portfolio Return), a 3D interactive globe with news markers, and a contextual news feed sidebar.

Backend endpoints used:

  • GET /news — fetches live news articles with geo-coordinates
  • GET /accounts/{id}/data — fetches live portfolio stats (polled every 5 seconds)

Live polling pattern:

useEffect(() => {
  const fetchPortfolio = async () => {
    const res = await axios.get(`${API_URL}/accounts/${activeAccountId}/data`, {
      headers: { Authorization: `Bearer ${token}` }
    });
    setStats(res.data.accountStats);
  };
  fetchPortfolio();
  const interval = setInterval(fetchPortfolio, 5000);   // Every 5 seconds
  return () => clearInterval(interval);                   // Cleanup on unmount
}, [activeAccountId]);

Why 5-second polling: The bot engine updates prices every 60 seconds. We poll every 5 seconds to ensure the UI feels responsive. The return () => clearInterval(interval) cleanup prevents memory leaks when the user navigates away.

Globe interactivity: Each news marker on the globe is an HTML element with a hover tooltip showing the headline, ticker, impact (Bullish/Bearish), and coordinates. Clicking a marker navigates to /news/{id} for the full AI analysis.

Key Defense Q&A — How to Explain Everything

Common Questions & Perfect Answers

Q: "Why did you choose React over Angular or Vue?"

A: React 19 was chosen for its component-based architecture, massive ecosystem (Globe.gl, Recharts, TradingView widgets all have React wrappers), and the team's familiarity with JSX. React's virtual DOM provides excellent performance for our data-intensive dashboard that polls live data every 5 seconds. Additionally, React's ecosystem has the best financial charting libraries and 3D visualization tools.

Q: "Why Zustand instead of Redux?"

A: Zustand is significantly lighter (1KB vs Redux's 7KB+), requires zero boilerplate (no reducers, action types, or Provider wrappers), and naturally works with React hooks. For our project's state complexity (2 stores: auth + accounts), Redux would be over-engineering. Zustand's getState() also lets us access store state outside React components (e.g., in async API calls), which Redux makes difficult.

Q: "How does the frontend stay in sync with the backend?"

A: We use polling-based real-time data. The Dashboard and TradingHub pages poll GET /accounts/{id}/data every 5 seconds using setInterval inside useEffect. We chose polling over WebSockets because: (a) the bot engine updates prices every 60 seconds, so 5-second polling is more than sufficient, (b) WebSockets add complexity and the data doesn't change fast enough to justify it, (c) polling is simpler to implement and debug.

Q: "How does authentication work end-to-end?"

A: User enters email + password → Frontend sends form-encoded POST to /auth/login → Backend verifies bcrypt hash against database → Backend creates a JWT with 30-day expiry containing the user's email → Frontend stores JWT in localStorage → Every subsequent API request includes Authorization: Bearer {token} header → Backend's get_current_user() dependency decodes the JWT to identify the user → If token expires, any API call returns 401, and our frontend auto-logs out.

Q: "Explain the 3D Globe on the dashboard."

A: We use react-globe.gl, which is a React wrapper around the Globe.gl library (built on Three.js for WebGL 3D rendering). The globe displays a high-resolution Earth texture from NASA's Blue Marble dataset. News articles from the backend /news endpoint include latitude/longitude coordinates assigned based on the financial center most relevant to the article (New York, London, Tokyo, etc.). These are rendered as interactive HTML elements on the globe surface using the htmlElementsData prop. Users can rotate the globe, hover for tooltips, and click markers to navigate to the full AI analysis page.

Q: "What would you improve if you had more time?"

A: (1) WebSocket connection for truly real-time price updates instead of polling. (2) Service Worker for offline capability and push notifications. (3) Mobile-responsive design (currently optimized for desktop). (4) Performance optimization with React.memo and useMemo for expensive re-renders. (5) End-to-end tests with Cypress or Playwright. (6) Accessibility improvements (ARIA labels, keyboard navigation).
